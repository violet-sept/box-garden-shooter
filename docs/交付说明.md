## 2. Web 部署（静态托管）

产物里**没有任何运行时资产**（没有 `public/`、没有音频文件、没有图片），所以"部署"就是把 `dist/` 整个传上去。
`vite.config.ts` 的 `base: './'` 让所有引用都是相对的，因此**子目录部署**（例如 GitHub Pages 的 `/<repo>/`）直接可用。
**托管在 GitHub Pages 上的完整步骤见 §2.5**（仓库里已经配好了工作流）。

### 2.1 缓存策略

| 路径 | 头 | 理由 |
|---|---|---|
| `assets/*` | `Cache-Control: public, max-age=31536000, immutable` | 文件名含内容哈希，内容变了文件名就变 |
| `index.html` | `Cache-Control: no-cache` | 它是唯一"名字不变但内容会变"的文件；必须每次回源校验 |

参考配置（托管方不同，写法不同，语义一致）：

```
# Netlify: public/_headers
/assets/*
  Cache-Control: public, max-age=31536000, immutable
/index.html
  Cache-Control: no-cache
```

```nginx
# nginx
location /assets/ { add_header Cache-Control "public, max-age=31536000, immutable"; }
location = /index.html { add_header Cache-Control "no-cache"; }
gzip on;             gzip_types text/html application/javascript;
brotli on;           brotli_types text/html application/javascript;   # 需 ngx_brotli
```

### 2.2 压缩

交给托管方开启 gzip / brotli 即可（实测压缩比见 §1 表格：three 分包 628 kB → gzip 156 kB / br 128 kB）。
**不要**自己生成 `.gz` / `.br` 兄弟文件：多数静态托管不会自动按 `Accept-Encoding` 选择它们，反而会把两份内容都传上去。

### 2.3 三条硬约束

1. **不要引入 CDN。** 整包里只有两条 URL，且都不会被请求：`http://www.w3.org/1999/xhtml`（XML 命名空间字符串）与 three.js 源码里的一条论文引用注释。这条是 Brief 的验收标准（"无任何外部 CDN 依赖（可离线运行）"）。
2. **不要引入 service worker。** 没有离线需求（整包一个文件都不缺），而 SW 会把"刷新后行为一致"变成需要调试的东西。
3. **不要改 `base`。** 改成 `'/'` 后 Web 端一切正常，但打包后的 `.exe` 窗口是**全黑**的（`file://` 下 `/assets/...` 指向盘根）——这是典型的"只有打包后才有"的不一致。

> 同一条规则在**运行时资产**上也成立：`PLAYER_MODEL_URL` 是 `'./assets/models/player/player.glb'`（**相对**）。
> 写成 `/assets/...` 时，桌面端会去盘根找、Pages 项目站会去 `https://<user>.github.io/assets/...` 找，
> 而"模型缺失"本来就是被支持的降级路径——于是**它会静默换成程序化占位体**，没有任何提示。
> 由 `tests/shell.test.ts` 钉住（见主文档 §5.15）。

### 2.4 本地等价物与实测

```powershell
npm run build
npm run preview     # http://127.0.0.1:4173
```

实测（阶段 5）：`/` 与两个 `assets/*.js` 全部 `200`，字节数与 `dist/` 中的文件逐一相符；构建产物中**零绝对 / 外部引用**；`index.html` 带 `Content-Security-Policy` meta。

### 2.5 GitHub Pages（仓库里已经配好一条路径）

**结论：可以，而且不需要为它改任何构建配置。** 产物是纯静态的（一个 HTML + 两个分包，零运行时资产），`base: './'` 让所有引用都是相对的，所以 `dist/` 挂上去就能玩——本地 `npm run preview` 就是它的等价物。

仓库里已经有 **`.github/workflows/deploy-pages.yml`**：推 `main`（或在 Actions 页手动 `workflow_dispatch`）就会 `npm ci` → `npm test` → `npm run build` → 把 `dist/` 当作 Pages artifact 发布。**GitHub 上只需要两步设置**：

1. 仓库必须是 **public**（免费账户的 Pages 只对公开仓库开放；私有仓库要 Pro / Team）。
2. **Settings → Pages → Source 选 “GitHub Actions”**。

地址由仓库名决定，两种形态都能直接用，**不需要改 `base`、更不要加 `--base`**：

| 仓库名 | 站点地址 |
|---|---|
| `<user>.github.io` | `https://<user>.github.io/` |
| 其它（例如 `box-garden-shooter`） | `https://<user>.github.io/box-garden-shooter/` |

（打开不带结尾斜杠的 `/box-garden-shooter` 会被 Pages 301 到带斜杠的形式，所以"相对于当前文档"的引用总是成立。）

**自定义子域名**（例如 `game.example.com`）：在 **Settings → Pages → Custom domain** 填域名，再到 DNS 服务商加一条 **CNAME 记录指向 `<user>.github.io`**，然后勾选 Enforce HTTPS。⚠️ **不要在仓库里加 `CNAME` 文件**——用 Actions 发布时 GitHub 既不创建也不读取它（官方原话："no `CNAME` file is created, and any existing `CNAME` file is ignored"），域名一律以仓库设置为准。

#### 与 §2.1 / §2.2 的两点差别（Pages 独有的限制）

| 项 | 在 Pages 上 |
|---|---|
| **自定义响应头** | **不支持**。§2.1 那套 `immutable` / `no-cache` 是给 Netlify / nginx / 对象存储用的，Pages 的缓存头由 GitHub 决定。代价不大但要知道：`assets/*` 的文件名带内容哈希，重新部署后自然换名；而 **`index.html` 名字不变**，所以**重新部署后的一小段时间里访客可能仍拿到旧的 `index.html`**——旧的会去要一个已被删掉的 `assets/index-<旧哈希>.js`。**这正是本地反复遇到的那件事，解法一样：Ctrl+F5。** |
| **压缩** | 由 Pages 自己开（gzip），同样**不能配置**。§2.2 的"交给托管方"在这里依然成立，只是托管方换成了 GitHub。 |

#### 国内访问的现实

`*.github.io` 在中国大陆的连通性不稳定（DNS 污染 / SNI 阻断），**"能打开"这件事本身不能承诺**。若要给国内的人玩，同一个 `dist/` 换一家即可，**不需要改代码**：Cloudflare Pages（支持私有仓库、免费）、Netlify、Vercel，或国内对象存储静态托管（阿里云 OSS / 腾讯云 COS + CDN）——§2.1 的缓存头配置在 Netlify / nginx 上是能真正生效的。

#### 验证边界（诚实口径）

- ✅ **已验证**：`dist/` 里所有引用都是相对的；把它挂在**子目录前缀**（`/box-garden-shooter/`，即 Pages 项目站的形状）下用 HTTP 取，`index.html` 与两个分包全部 `200`，**服务端字节与磁盘逐一致**；整包只有两条不会被请求的 `http(s)` URL，`eval` / `new Function` 计数为 0。

## 4. ⚠️ 本机沙箱做不到的事（阶段 5 的真实边界）

受限沙箱**拒绝一切 Chromium 进程**（`FATAL:mojo\...\platform_channel.cc:108 ... 拒绝访问 (0x5)`），
`electron-builder` 的模块收集器还会 `spawn EPERM`。所以下面六件事**必须在普通（非沙箱）终端里补**：

| # | 待办 | 命令 | 判据 |
|---|---|---|---|
| 1 | 打包并验收产物 | `npm run desktop:build` → `npm run desktop:accept -- --target packaged` | `report-packaged.json` 里 `ok: true`。**2026-09-15 进展**：`win-unpacked` 已产出；NSIS 安装包未出现；`--target packaged` 因 `connect EACCES 127.0.0.1:9333` 失败**而应用本身启动正常**——重跑一次，仍失败就加 `--port 9411` |

## 5. 阶段 5 修掉的验收门槛缺陷（重要）

阶段 5 在本机读到了上一次**真实非沙箱运行**留下的报告与截图，两者的矛盾暴露了两个假阳性。
它们都不是游戏 bug，而是**验收断言本身永远不会通过**——`--target packaged` 因此不可能全绿。

| # | 断言 | 症状 | 根因 | 修法 |
|---|---|---|---|---|
| 1 | `canvasContent.spread > 12` | 报告写 `spread 0 / mean 0 / opaque 0`，而**同一次运行的截图里是完整的竞技场、HUD 与敌人** | 渲染器是 `preserveDrawingBuffer: false`；合成之后绘制缓冲就被清掉了，把 WebGL 画布 `drawImage` 到 2D 画布再读像素**必然是空的** | 改成解析 `Page.captureScreenshot` 的 PNG（**合成后的那一帧，也就是玩家真正看到的东西**），两条断言：整帧有对比度 + 一条不含 HUD 的场景带也有对比度 |
| 2 | `logErrors.length === 0` | 缺失的可选资产 `player.glb` 让整轮 FAIL | 同一个失败走**两条**通道：`Network.loadingFailed`（D12 已白名单）**和** `Log.entryAdded`（没被白名单）。D12 只修了一半 | 两条通道用同一套双向断言：`required` 必须为 0，且被豁免的条目必须**点名** `player.glb`（URL 或文本） |

顺带修掉两条"测了等于没测"的地方：

- **`requestCount: 0`**：脚本在页面加载完之后才 attach，于是"零非 `file://` 请求"这条断言**什么都没观察到**。
  现在连上后强制 `Page.reload` 一次，请求与失败加载才真正被观察到（`requestCount > 0` 本身也成为一条断言）。
- **假产物**：`electron-builder` 在模块收集器失败**之前**就把 Electron 框架拷进了 `release\win-unpacked\`，
  于是 `findPackagedExe()` 会找到 `electron.exe` + `resources\default_app.asar`（Electron 自带的示例应用）。
  现在 `--target packaged` 会先确认存在 `resources/app.asar`（或 `resources/app/package.json`），
  否则直接报"这是一次被打断的构建"，而不是让失败伪装成"游戏没画出 canvas"。

这些逻辑**都有单测**（`tests/acceptanceGate.test.ts`，13 例；含"整帧通过但场景带为平色必须失败"这一例），
因为本机跑不了 Chromium，单测是它们唯一的证据。
交付面（CSP / preload 暴露面 / 打包白名单 / `base` / 图标 / README 命令 / **Pages 发布工作流与相对资产路径**）另有一组钉子：
`tests/shell.test.ts`（17 例）。

> 计数说明：`shell` 从 12 → 14（启动缺陷收尾，§5.13/§5.14）→ **17**（阶段 5 新增 3 例：相对资产 URL、Pages 工作流的权限与
> artifact 路径、"不得为托管方改 `base`"）→ **22**（阶段 7 起：暂停菜单的静态标记与接线、**阶段 10 起**：倒计时元素的静态标记、**阶段 11 起**：`#interact` 的静态标记与"开屏说明里的按键与绑定一致"）；`acceptanceGate` 从 10 → 13。**这几个数是阶段 5 的旧计数**；全套在**阶段 11 重测为 27 文件 / 592 例**（阶段 10 是 26 / 552，阶段 9 是 26 / 557；**阶段 11 净 +40，一例未删、一例未放宽**：新建 `tests/pickups.test.ts` 12 例 · `enemies.test.ts` 44 → 54（`Gunship` 一节 10 例 + 医疗箱回血 1 例）· `director.test.ts` 22 → 26（第二批的四个相位）· `views.test.ts` 45 → 54（直升机机体与旋翼、补给箱视图、HUD 两处接线）· `hud.test.ts` 24 → 26（第二批文案、拾取提示）· `input.test.ts` 22 → 24（`E` = 交互 / `Q` = 投掷）· `weapon.test.ts` 21 → 22（`grantReserveAmmo`），另在 `world-run-loop.test.ts` 与 `shell.test.ts` 的原有例子里加了断言）。阶段 10 那一轮的净 −5 例（曲线换脚本）分解见主文档 §0.1。

## 6. 决策记录（S1–S7）

| 编号 | 议题 | 结论 |
|---|---|---|
| **S1** | sourcemap 策略 | **保持 `sourcemap: true`；Web 连 `.map` 一起上传，桌面包用 `!**/*.map` 排除**。理由见 §1 的引用块 |
| **S2** | 版本号与可执行文件名 | **版本提到 `1.0.0`**（首个完整交付构建）；**`productName` 保持中文**，新增 `win.executableName: box-garden-shooter`，快捷方式仍是 `箱庭射击` |
| **S3** | 退出确认 | **不做。** 判断"这一局是否进行中"要求主进程知道渲染进程的游戏状态，也就是**新增一条 IPC 通道**，直接违反"preload 暴露面保持最小"这条硬规则；而本版没有存档与进度，误关窗口的代价接近零。**"不做"是有理由的结论，不是遗漏**（`tests/shell.test.ts` 钉住 `main.cjs` 里不出现 `ipcMain`） |
| **S4** | 打包图标 | **程序化生成**（`tools/make-icon.mjs`，零依赖，`npm run assets:icon`）。`build\icon.ico` 含 16/24/32/48/64/128/256，256 那条是 electron-builder 的硬要求 |
| **S5** | Web 部署形态 | **静态托管 + 托管方压缩 + 内容哈希长缓存 / `index.html` no-cache**，子目录可用；**不引 CDN、不引 service worker**。详见 §2 |
| **S6** | 双端一致性怎么判 | **同种子 `--scene perf` 读数比对（人工，两端各一次）**：`ticks` / `kills` 必须逐点一致（同种子 + 同固定步长），两端 `fps` 均需 ≥ 59；WASD / 左键 / 右键 / `R` / **`Q`（投掷）** / **`E`（拾取）** 六项在两端各确认一遍。**不新增 `--target web` 工具**（浏览器版本不受控，它的失败不能当"Web 构建坏了"的判据） |
| **S7** | Web 端"点开网址就能玩"怎么落地 | **GitHub Pages + 官方 Actions 工作流**（`.github/workflows/deploy-pages.yml`）：产物就是 `dist/`，**不为托管方改 `base`**，自定义域在仓库设置里配、**不加 `CNAME` 文件**。连带定下一条硬规则：**运行时资产 URL 必须相对**（`PLAYER_MODEL_URL` 已从 `/assets/...` 改成 `./assets/...`），否则桌面端与子目录托管都会静默降级成程序化占位体。见 §2.5 与主文档 §5.15 |

## 7. 一句话总结

> 阶段 5 的产出不是"更多功能"，而是**一份能双击运行、能离线跑、两端一致的产物，和一份别人照着就能上手的说明**。
> 本机补完的是**构建 / 配置 / 壳 / 文档 / 验收门槛**；剩下那一组"必须有真实画面、声音与帧率"的验收，
> 只有在普通终端里跑 §4 那几条命令才能闭环——**它们不需要改代码**。
>
> **Web 端另有一条不需要终端、也不需要本机的路**：把仓库推到 GitHub（public）、Settings → Pages 选 "GitHub Actions"，
> 之后每次推 `main` 都会自动发布到 `https://<user>.github.io/<repo>/`。见 §2.5——**唯一还缺的证据是"在真实浏览器里点一次"**。
