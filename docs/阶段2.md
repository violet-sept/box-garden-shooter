## 1. Brief 浓缩（完整 Brief，来自主文档 §1）

### 1.1 定位与三个目标

做一个**能立刻上手、单手就能玩明白**的小型 3D 箱庭射击游戏：玩家站在围栏圈起的立体沙盘里，一边用步枪点掉成群扑上来的小敌人，一边等那个慢慢走过来的大块头，然后决定是继续清杂兵还是先把子弹喂给它。

按优先级排序的三个目标：

1. **验证一套可复用的 Three.js 游戏骨架**——"输入 → 固定步长模拟 → 渲染"分层、可测试、能直接长出第二个游戏。
2. **把"一套代码两端发布"跑通**——Web 即时可玩，桌面端一个双击就能进的原生窗口；同一份 `src/`，差异只允许在薄壳层。
3. **用最小的内容量换最大的可玩性**——两种敌人、两种攻击模组、一张地图，靠**节奏设计**而不是内容堆量撑起 10–15 分钟一局。

### 1.2 目标体验曲线

| 阶段 | 时长 | 玩家感受 | 系统在做什么 |
|---|---|---|---|
| 熟悉 | 0:00–0:30 | "这地方多大？枪手感如何？" | 空场地 + 计时器，允许无压力试枪 |
| 升温 | 0:30–3:00 | "它们在包我，得动起来" | 小敌人 3–6 只成波投放，逼玩家走位 |
| 压力 | 3:00–6:00 | "弹药有点紧，注意换弹时机" | 小敌人数量爬升，投放间隔缩短 |
| 转折 | 6:00–7:30 | "大块头来了，杂兵还没清完" | 大敌人登场（清场或超时触发），两种模组同时施压 |
| 收束 | 7:30–12:00 | "先躲轰炸，再处理小兵" | 双模组优先级判断，道具投掷成为翻盘手段 |

**核心体验关键词：清晰、紧凑、有节奏。** 不追求拟真，不追求叙事。

### 1.3 核心玩法循环

```
    观察威胁 ──► 移动/走位 ──► 瞄准(右键) ──► 射击(左键)
        ▲                                          │
        │                                          ▼
    道具投掷(E) ◄── 判断时机 ◄── 弹匣告警 ◄── 换弹(R)
        │                                          │
        └──────────► 敌人减员 ──► 波次推进 ────────┘
```

### 1.4 操作方案（**已锁定，不得擅自更改**）

| 输入 | 行为 | 备注 |
|---|---|---|
| `W` / `A` / `S` / `D` | 摄像机局部坐标系的 ±forward / −right | **方向按相机朝向解算，不按角色模型朝向**；角色转头动画去追移动方向 |
| 鼠标左键 | 射击 | 按住持续射击（全自动） |
| 鼠标右键 | 开镜瞄准（ADS） | 按住生效；FOV 78°→45°，移速 ×0.55，扩散 3.4°→0.35° |
| `R` | 换弹 | 可打断窗口 0.35s；空仓更快（1.7s vs 2.1s） |
| `E` | 道具投放 | 抛物线，1.4s 引信，5.5m 溅射（**阶段 3 才实现**） |
| `Shift` / `Space` | 疾跑 / 跳跃 | 辅助键 |
| `Esc` | 释放鼠标 | 引擎级行为，同时作为暂停 |

### 1.5 两种敌人（`src/core/config.ts` 的 `ENEMY_SMALL` / `ENEMY_LARGE`）

#### 小型敌人 `Stalker`（潜袭者）—— 消耗品式的压力源

- **模组**：冲锋 + 接触近战。提速至 9 m/s 扑向玩家，进入 1.5m 触发 **0.42s 抬手**，命中 9 点伤害，随后 0.55s 硬直。
- **视觉读条**：抬手时躯干前倾 + 体表发光。这是玩家判断"该后撤了"的**唯一依据**。
- **数值**：HP 60 · 移速 5.2 · 伤害 9 · 冷却 1.1s · 弱点 ×2.8。
- **设计意图**：60 HP 意味着**躯干 3 枪 / 爆头 1 枪**（`22 × 2.8 = 61.6 ≥ 60`，仅 22m 内满伤时成立）。爆头奖励必须足够大，否则玩家没有理由去瞄。
  > 倍率是 **2.8 而非 2.5**（主文档决策 D6）。2.5 只有 55 点、要 2 枪。**不要改回 2.5。**

#### 大型敌人 `Warden`（典狱长）—— 节奏破坏者

- **模组**：远程范围轰炸。26m 内进入攻击，**1.35s 长抬手**（带明显落点指示器），召唤 3 发延迟爆发的范围伤害，单发 34 点，冷却 2.8s。
- **与小型敌人的本质差异**：小型敌人惩罚"站着不动"，大型敌人惩罚"待在开阔地"。两者叠加时玩家被迫在"躲轰炸"和"清杂兵"之间取舍——**这就是这个游戏全部的策略深度**。
- **数值**：HP 2400 · 移速 1.9 · 伤害 34 · 冷却 2.8s · 弱点 ×1.6。
- **设计意图**：**躯干 110 发（≈3.7 匣）/ 爆头 69 发（≈2.3 匣）**。击杀必然需要一次主动换弹，而换弹时它还在输出——这就是压力来源。
  > "约 2 个弹匣"是初版 Brief 的错误口径，已由决策 D7 改为按实算写两个口径。**不要再写"约 2 个弹匣"。**
- **狂暴阶段**：HP ≤ 35% 进入 `ENRAGE`，**只压缩收招时间与冷却（×0.75），绝不压缩抬手时间**。狂暴是**数值修正量**，不是一套新状态机。

### 1.6 群体攻击的"槽位"约束（小敌人可读性的关键）

```ts
// 同一时刻最多 ATTACK_SLOTS 只小敌人处于 TELEGRAPH/ACTIVE 状态
const ATTACK_SLOTS = 3;
// 未拿到槽位的敌人停在 CHASE 的外围，做"蓄势"姿态但不出手
```

没有这条约束，8 只小敌人会在同一秒内把伤害全灌到玩家身上，读感是"我瞬间暴毙"而不是"我没躲好"。拿到槽位的才是威胁，其余在外圈游走等待——**注意力负担恒定，压迫感不减**。

### 1.7 投放规则（阶段 3 实现，但**接口现在就要留好**）

```
波次开始
   ├─► 小敌人按 spawnInterval 逐个投放（受 maxConcurrentSmall 约束）
   └─► 同时启动两条"大敌人解锁"判据，取先满足者：
         (A) 小敌人全部被消灭   ← 玩家行为驱动（正反馈）
         (B) 计时器到期          ← 时间兜底（Wave1: 75s，每波 ×0.97，下限 40s）
```

- 大敌人存活期间小敌人**继续以较慢间隔补充**（`addsWhileBossAlive`），避免"打完 Boss 就没事干"。
- **投放点选择**：环形候选点中筛选，要求距玩家 14–40m、彼此间隔 ≥3.5m、且不在玩家视野正前方 60° 锥内——**绝不允许在玩家脸上刷怪**；全部被过滤时放宽条件兜底，而不是刷不出来。

> 阶段 2 需要留的接口：`spawnEnemy(archetype, position)` 必须是**纯函数式注入位置**的形式，而不是"敌人自己找地方站"。投放点筛选属于阶段 3 的 `director/spawnPoints.ts`。

### 1.8 资产策略与人物模型接入约定

| 类别 | 来源 | 处理方式 |
|---|---|---|
| 人物模组 | **委托方提供** | 资产到位前用程序化胶囊体占位，**不阻塞任何开发** |
| 地图模组 | Three.js 基础几何体程序化拼装 | `BoxGeometry` / `CylinderGeometry` + 复用材质 + `InstancedMesh` |
| 道具模组 | 程序化生成 | 投掷物 = `SphereGeometry` + 自发光；爆炸 = 粒子 + 面片 |

交付方必须满足的约定：

```
public/assets/models/player/
  ├─ player.glb            # 必需，单文件，内嵌动画
  └─ (可选) player_ads.glb # 专用开镜姿态（无则用动画层混合）
```

- **单位**：米。身高约 1.75m，站立时脚底在局部原点 `y = 0`，**面朝 `+Z`**。
- **骨骼**：AnimationClip 命名需**包含**（大小写不敏感的关键字匹配）：`idle` · `walk` / `run` · `shoot` / `fire` · `reload` · `death` / `die`。
- **格式**：`.glb`（非 `.gltf` + 外部 bin）；Draco 可选但要同步给 decoder。
- **面数**：建议 ≤ 30k 三角面。
- **缺失降级**：任一 Clip 缺失 → 回落到最接近的状态（`run`→`walk`→`idle`），**并在控制台明确告警**，绝不崩溃。

## 3. 现状接线：敌人插进哪里

### 3.1 `World.tick()` 的顺序（承重结构，不要重排）

```
tick(dt, intent):
  1. 时间缩放（hitstop：scaledDt = dt * 0.12，预算按真实 dt 递减）
  2. 武器决策          tickWeapon(...)
  3. 玩家移动          tickPlayer(player, scratch, collision, intent, scaledDt, time)
  4. 重解瞄准          solveAim(aim, scratch, player, collision.solids)
  5. 目标同步          targets.sync(scaledDt, time)      ← 敌人 AI 与命中盒重建插在这里之前
  6. 射击              if (weaponResult.fired) performShot()
  7. 道具              (阶段 3)
  8. 清理              (阶段 2) 回收死亡实体、归还对象池
```

**插入点（三处，别放错）：**

| 位置 | 放什么 | 理由 |
|---|---|---|
| 第 4 步与第 5 步之间 | `enemies.tick(dt)`：所有 AI 状态推进、移动、攻击计时 | 必须在**命中盒重建之前**，否则这一 tick 的射击打的是上一 tick 的位置 |
| 第 5 步内 | `enemies.sync()`：按新位置重建 `head` / `body` 命中盒 | 与 `targets.sync()` 同性质；`hitscan` 读的是这份数据 |
| 第 6 步后 / 第 8 步 | 敌人死亡回收、`ATTACK_SLOTS` 槽位归还、对象池归还 | 在同一 tick 内完成，避免"尸体还占着命中盒" |

**敌方攻击玩家**也应当在第 6 步附近结算（在玩家移动之后），这样"这一 tick 玩家跑到哪"与"这一 tick 被打没打到"是同一个世界状态。

### 3.2 `TargetStore` 是敌人框架的前身（照抄形状，不要另起炉灶）

现状（`src/game/targets.ts`，224 行）：

```ts
interface Target {
  readonly id: number;
  readonly spec: TargetSpec;
  readonly maxHealth: number;
  readonly weakPointMultiplier: number;   // 挂在受击体上，不是全局常量
  readonly hitboxes: TargetHitbox[];      // [0] 恒为 weak point（head）
  readonly position: Vector3;             // 脚底位置
  readonly velocity: Vector3;             // 给 lead-prediction 用
  health: number;
  alive: boolean;
  lastHitTime: number;
  totalDamageTaken: number;
}

interface TargetStore {
  readonly targets: readonly Target[];
  sync(dt: number, time: number): void;                 // 每 tick 重建命中盒
  byId(id: number): Target | undefined;
  applyDamage(target, amount, zone, point): Target | null;  // 返回"死了的那个"
  aliveCount(): number;  damagedCount(): number;  reset(): void;
}
```

**它已经被 `hitscan.ts` 直接消费**（`targets.targets` / `target.alive` / `target.hitboxes` / `target.weakPointMultiplier`），所以替换成敌人就是把 `spec: TargetSpec` 换成 `stats: EnemyStats` + 一个 FSM 状态字段。

**两条路线，任选其一（这是本阶段第一个要落的决策，记为 D8）：**

| 路线 | 做法 | 代价 |
|---|---|---|
| **A（推荐）单一仓库** | 把 `targets.ts` 演进为 `game/enemies/` 下的仓库：条目带 `archetype: 'small' \| 'large' \| 'dummy'`；静态靶作为 `'dummy'` 继续存在（调试与手感回归仍需要它） | `hitscan.ts` 的调用面几乎不动；`tests/world.test.ts` 的 18 例只需极少量改动 |
| B 双仓库 | 保留 `TargetStore`，另建 `EnemyStore`，`hitscan` 同时查询两个来源并比距离 | 两处维护同样的命中盒逻辑；`hitscan` 要多一层合并，容易写成"先查 A 再查 B"从而破坏距离排序 |

**无论选哪条，命中查询的不变式不能破**：关卡 `blockers` 与**所有**可命中体必须在**同一轮距离比较**里取最小 `t`。这就是"5m 的墙永远赢过 9m 的敌人"。

### 3.3 命中链路现状（解析式，不是 `Raycaster`）

```
hitscan.fire(origin = 枪口, aimedAt = 准星点, spreadDeg)
  ├─ 扩散：以视线基构造正交基，sqrt(rng.next()) 取锥内偏角（两次随机，可播种）
  ├─ traceLevel(origin, dir, WEAPON.range)   → 最近的关卡 blocker
  ├─ traceTargets(origin, dir, levelHit.t)   → 最近的命中盒（t 必须小于关卡命中）
  ├─ 取更近者；关卡命中直接结束（造 `bullet:impact`）
  ├─ 命中敌体：alreadyHit 防同一发重复结算 → resolveDamage() → emit 'hit:registered'
  └─ 最后统一 applyDamage()：掉血 / 死亡 / 事件都在这里发生
```

要点：

- **`weakPointMultiplier` 来自受击体**（`target.weakPointMultiplier`），因为两种敌人的倍率不同（2.8 / 1.6）。`hitscan.ts` 里还有个 `weakPointMultiplierFor(kind)` 的导出，**目前无人调用**，就是留给本阶段做按 archetype 取值的单点。
- **一次射击一个 `shotId`**，`alreadyHit: Set<number>` 保证同一发不会对同一目标结算两次。
- **伤害管线**：`命中 → 弱点倍率 → 距离衰减 → 护甲减伤 → 击退冲量 → 派发事件`，全程纯函数 + 事件。护甲（armour）目前未实现，如果需要就在 `damage.ts` 里加，不要塞进 `hitscan.ts`。
- **`hitscan.ts` 里 `traceEnd()` 也是无人调用的导出**，留给调试面板。

### 3.6 敌人碰撞（主文档没明写，但必须做）

敌人**不能穿箱子**。直接复用玩家那套：

```ts
const collision = createCollisionWorld(level);   // 已存在，World 里就有
// collision.obstacles：实心几何（不含地面板，避免每 tick 把实体弹起来）
// collision.solids：还挡子弹与视线（= blockers，去掉围栏）
// collision.halfSize：24，用于把敌人夹在场地内
```

- 水平解算用 `core/math/intersect.ts` 的 `resolveCapsuleAabb`（玩家控制器用的同一个函数），把敌人的 `radius` / `height` 传进去。
- 地面上：敌人只需要"贴地"（arena 地面是平面 + 少量平台），不需要跳跃；简单做法是把 `y` 夹到地面高度。**若要上平台，照抄玩家的地面探测（`stepHeight` / `groundSnapDistance` 的思路），不要重新发明。**
- 实体数量 ≤ 14（`DIRECTOR.maxConcurrentSmall`），每 tick 对 ~40 个 AABB 做解算，性能预算内（模拟 tick ≤ 2ms）。

## 5. 硬规则（违反即驳回）

1. **`src/game/**` 不得 import Three.js 渲染类**（`Mesh` / `Scene` / `Material` / `WebGLRenderer`）。`Vector3` / `Quaternion` / `MathUtils` 这类纯数学类型可以，但本项目已有自己的 `core/math/vec3.ts`，**优先用它**。
2. **`src/render/**` 不得包含游戏规则判断**（不出现"如果血量小于 0"）。
3. **只有 `src/main.ts` 允许接触 `document` / `window`。**
4. **所有数值进 `src/core/config.ts`**，任何地方不得出现魔法数字。
5. **所有时间相关的量必须乘 `dt`**；射速/冷却用**累加器** `x += 60 / rpm`，不用赋值。
6. **hitstop 用模拟时间缩放实现，绝不"跳过 N 个 tick"。**
7. **随机一律 `core/math/rng.ts` 的可播种 `Rng`**，禁止 `Math.random()`。
8. **短生命周期对象必须池化**（命中贴花、特效粒子、伤害数字；敌人的视图对象同样池化复用）。
9. **攻击抬手时间（telegraph）永远不可压缩**——加难度只压缩收招与冷却。
10. **命中查询保持解析式**（`core/math/intersect.ts`），**不要把权威判定换成 `Raycaster`**。若渲染侧需要拾取，也必须以 `hitscan.ts` 的结果为准。
11. **弹道方向取自 `PlayerState` 的 yaw/pitch**，绝不取自渲染相机姿态；后坐力只是表现偏移。
12. **测试文件用 `#/...` 导入源码**（不用 `@/...`），且**只写 ASCII**（`×` / `°` / `§` 都改成 `*` / `deg` / `section`——早前有 12 处注释因此被编码往返损坏，其中一处还落在测试名里）。

## 6. 本阶段的已知陷阱

| 陷阱 | 症状 | 正确做法 |
|---|---|---|
| **`Object3D.layers` 不被子节点继承** ★ | GLTF 角色"射线只在 layer 0 生效"，命中判定静默失效 | **在 `traverse()` 里逐个 mesh 设层**，无一例外：`o.layers.disableAll(); o.layers.enable(LAYER_HITTABLE); o.userData.hitZone = inferZone(o)`。阶段 1 的靶子是解析式盒/球、不经过 `layers`，所以这条**从本阶段才真正生效** |
| 把手/身命中盒当成"从模型里读" | 模型换一版，命中盒与外观错位 | 命中盒由 `EnemyStats.radius/height` **解析式生成**，与外观解耦；模型只负责好看 |
| 敌人叠在一起 | 一群敌人挤成一个点，玩家不知道该打谁 | 分离力（`steering.separation`）+ 只对"最近的一只"结算攻击 |
| 群攻同时出手 | 玩家半秒内被打 6 下，读感是"瞬间暴毙" | `ATTACK_SLOTS = 3` |
| 抬手被"为了更难"缩短 | "难"变成"不公平" | 见硬规则 9 |
| 狂暴写成新状态机 | 两套时序逻辑，平衡性调整要改两处 | 狂暴只是**数值修正量**（冷却/收招 ×0.75） |
| 敌人在 `targets.sync()` 之前推进 | 打中的是上一 tick 的位置，移动目标总是"差一点" | AI 推进必须在命中盒重建之前（§3.1） |
| 门/围栏挡住子弹 | 玩家觉得"隔着栅栏打不到"是 bug | 围栏**只挡人不挡子弹**（`level.blockers` 里已排除围栏），敌人同理 |
| 敌人在玩家脸上生成 | 体验直接崩 | 阶段 3 的筛选（14–40m、≥3.5m 间隔、视野外 60°、兜底）——本阶段先保证 `spawnEnemy` 接受外部传入的位置 |
| `spreadDeg` 的 `tan()` 捷径 | 扩散锥在大角度处被压扁 | 已有实现用"均匀角度 + `sqrt` 半径"，别改 |
| 长时间不清理死亡实体 | 命中盒还在、对象池不归还，帧率缓慢下滑 | 第 8 步清理必须真的执行；`alive` 判定进 `hitscan` 已经做了（`if (!target.alive) continue`），但视图与池要自己还 |

// game/enemies/frames.ts —— 攻击编码成数据，而不是代码
export interface AttackFrame {
  readonly telegraphTime: number;  // 抬手：可见预兆，伤害未生效
  readonly activeTime: number;     // 生效：伤害窗口
  readonly recoveryTime: number;   // 收招：玩家的输出窗口
}
export type FramePhase = 'TELEGRAPH' | 'ACTIVE' | 'RECOVER' | 'DONE';
export function phaseAt(elapsed: number, frame: AttackFrame, cooldownScale: number): FramePhase;
//   cooldownScale 只乘 recoveryTime（狂暴），telegraphTime 永不被缩放

// game/enemies/EnemyState.ts
export interface EnemyState {
  readonly id: number;
  readonly archetype: EnemyArchetypeId;   // 'small' | 'large'
  readonly stats: EnemyStats;
  readonly hitboxes: TargetHitbox[];      // [0] = head（weak point）
  readonly position: Vector3;             // 脚底
  readonly velocity: Vector3;
  fsm: SmallState | LargeState;
  health: number;
  alive: boolean;
  /** 攻击时序；由 FSM 置位，由 frames.ts 解释 */
  attackElapsed: number;
  attackCooldown: number;
  hasAttackSlot: boolean;                 // 小敌人的并发槽位
  lastHitTime: number;
  enraged: boolean;
}

  dispose(): void;
}
