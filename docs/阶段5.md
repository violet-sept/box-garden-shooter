> ### ✅ 阶段 5 在本机额外修掉的：两个"只要不修就永远无法验收"的门槛缺陷
>
> 本机虽然起不了 Chromium，但上一次**真实非沙箱运行**留下的 `.tmp-accept/report-shell.json` 与
> `screenshot-shell.png` 都在。把两者放在一起读，暴露了两个**假阳性**——它们不是游戏 bug，而是**验收断言本身错了**，
> 只要不修，`--target packaged` **永远不可能全绿**：
>
> | # | 断言 | 症状 | 根因 |
> |---|---|---|---|
> | 1 | `canvasContent.spread > 12` | 报告写 `spread 0`，而**同一次运行的截图里是完整的竞技场、HUD 与敌人** | 渲染器是 `preserveDrawingBuffer: false`；合成后绘制缓冲即被清空，把 WebGL 画布 `drawImage` 到 2D 画布再读像素**必然读到空的** |
> | 2 | `logErrors.length === 0` | 缺失的可选资产 `player.glb` 让整轮 FAIL | 同一个失败走**两条**通道：`Network.loadingFailed`（D12 已白名单）**和** `Log.entryAdded`（没被白名单）。**D12 只修了一半** |
>
> 修法：① 改读 `Page.captureScreenshot` 的 PNG（合成后的那一帧，也就是玩家真正看到的），断两条——整帧有对比度 + **一条不含 HUD 的场景带**也有对比度；② 两条通道用**同一套双向断言**（`required` 必须为 0，被豁免的条目必须**点名** `player.glb`）。**阈值与"零容忍"的方向一寸没让，改的是测量对象与分类方式。**
> 另修两处"测了等于没测"：`requestCount: 0`（连上后强制 `Page.reload`，让"零非 `file://` 请求"真的观察到请求）与"部分 `win-unpacked`（裸 Electron）冒充产物"（启动前校验 `resources/app.asar`）。
> **全部有单测**：`tests/acceptanceGate.test.ts`（13 例）。细节见主文档 [§5.12.1](../docs/PROJECT_TECHNICAL_PLAN.md#5121-两条再怎么跑也永远不会变绿的验收断言本轮最重要的发现)。

**打包的两条离线解法**（[§5.6.6](./PROJECT_TECHNICAL_PLAN.md#566-桌面端验收执行路径清单已核实)，实测有效）：`electron-builder` 卡在下载 `electron-v44.3.0-win32-x64.zip`（GitHub 超时）时，用下面两条中的任一条绕开那次下载：

| # | 做法 | 需要网络？ |
|---|---|---|
| **A（推荐）** | `npm run desktop:build -- --config.electronDist=node_modules\electron\dist` | **不需要** |
| B | 先设 `$env:ELECTRON_MIRROR='https://npmmirror.com/mirrors/electron/'` 再打包 | 需要（镜像；即便 zip 命中缓存，`@electron/get` 仍会去拉 `SHASUMS256.txt` 校验文件） |

> ⚠️ **阶段 5 收尾清理时，`.tmp-electron-cache\<url-hash>\` 里那份 158 MB 的 `electron-v44.3.0-win32-x64.zip` 已被删除**（用户要求清掉开发期临时文件）。
> 于是**原先的第三条路线（`electronDist` 直接指向该 zip 所在目录）已失效——不要照旧文档敲那条命令，它会报找不到目录**。
> 路线 A 不依赖它：`node_modules\electron\dist` 是**已解压**的 246 MB 发行目录（`electron.exe` 在位），
> 走的是 `copyDir` 分支，**同样完全不联网**。**代价要如实记住**：若日后清空 `node_modules`，
> 离线打包的兜底也就没了，得先联网（或用镜像）重下 Electron。

> ⚠️ **参数必须用长写法 `--config.electronDist=`**（阶段 5 实测）。electron-builder 文档里的短写法
> `-c.electronDist=...` 会被解析成"配置文件 `.electronDist=...`"，直接
> `ENOENT: no such file or directory, open '<cwd>\.electronDist=...'` 退出。
> 长写法会打印 `using custom unpacked Electron distribution  electronDist=...`。

> ⚠️ **`.tmp-*/` 在 `.gitignore` 里**，所以那些缓存/报告**都不进版本库**。
> ⚠️ **winCodeSign / NSIS 是另一批下载**，与 Electron 无关：`$env:ELECTRON_BUILDER_BINARIES_MIRROR='https://npmmirror.com/mirrors/electron-builder-binaries/'`。
> ⚠️ **不要设**（那是沙箱内的补偿手段，普通终端设了只会把缓存搬进工作区）：`ELECTRON_CACHE` / `electron_config_cache` / `ELECTRON_BUILDER_CACHE` 重定向、`--cache .tmp-npm-cache`、`--ignore-scripts`。

### 1.2 双端一致性策略（主文档 §2.5 的可执行版）

一致性的**结构性保证**已经存在，阶段 5 要做的是把它变成读数：

| 保证 | 现状 |
|---|---|

### 3.4 Electron 打包怎么做

**打包命令链**：`npm run desktop:build` = `npm run build` **然后** `electron-builder --config electron-builder.yml`。注意三点：

1. **`files` 是白名单**：`dist/**/*` + `electron/**/*` + `package.json`。所以 `src/` / `tests/` / `node_modules` **都不进包**；`three` 之所以能跑，是因为它已经被 Vite 打进 `dist/assets/three-*.js`（它待在 `devDependencies` 里正是这个原因）。
2. **`extraMetadata.main: electron/main.cjs`** 让包内的 `package.json` 指向壳，而**仓库里的 `package.json` 一行不改**（Web 端的 `npm run dev` 故事保持干净）。
3. **`npmRebuild: false`**：本项目没有原生依赖，而 electron-builder 的重建步骤会 `fork` 一个 `npm rebuild` 子进程——在受限沙箱里直接 `spawn EPERM`。**如果将来加了原生模块，第一件事是把它打开。**

**两条必须记住的环境事实**（[§5.3.1](./PROJECT_TECHNICAL_PLAN.md#531-桌面端为什么在沙箱里起不来)）：

- **Electron 在受限沙箱里根本起不来**（Chromium 的 IPC 走命名管道，`platform_channel.cc:108 ... 0x5`；`--no-sandbox` / `--single-process` / `--in-process-gpu` / `--disable-gpu` 及其组合全部在同一处失败，已逐一验证）。
- **`electron-builder` 也起不来**：它的 node-module collector 会 `spawn` 一个 `npm list`，`spawn EPERM`，**且没有配置开关能跳过它**。

所以：**打包与打包产物验收都必须在非沙箱终端里做。**

## 5. 硬规则（违反即驳回）

继承主文档 §2.2 / §4.1 与阶段 3 / 4 §5，阶段 5 每条都要遵守：

1. **`src/game/**` 不得 import Three.js 渲染类**；`src/render/**` 不得包含游戏规则判断；**只有 `src/main.ts` 允许直接接触 `document` / `window`**（宿主机能力走 `src/platform/**`）。
2. **所有数值进 `src/core/config.ts`**。阶段 5 **不应新增任何游戏数值**。
3. **固定步长不可破坏**：模拟只走 `core/loop.ts`，所有时间量乘 `dt`。**打包不会改变这条，但"顺手加个 `requestAnimationFrame` 里积分"会。**
4. **随机一律 `Rng`**，禁止 `Math.random()`（`PERF.seed` 是双端一致性回归的基础）。
5. **不改阶段 1–4 已定案的手感与玩法数值**：`PLAYER` / `CAMERA` / `WEAPON` / `ENEMY` / `WARDEN` / `DIRECTOR` / `ITEMS` / `AUDIO` **逐字冻结**。阶段 5 **没有**调参授权；真要调，先给出真人局读数，并同步主文档与 `SKILL.md`。
6. **preload 暴露面不扩大**：`contextBridge` 现在只暴露一个冻结的 `{ isDesktop, electron }`。**新增任何 IPC 通道都必须先说明理由**（S3 的取舍就是被这条规则逼出来的）。
7. **`base: './'` 不得改成 `'/'`**，产物里的引用必须保持相对——否则打包后的窗口是全黑的，而 Web 端一切正常（最难查的一类不一致）。
8. **包内不得出现任何外部请求**：`dist/` 的静态 URL 检查 + `desktop:accept` 的 `requestCount === 0` 是两条证据，**不要靠"我看着没有"**。
9. **不把 `node_modules` / `src` / `tests` 塞进包**：`files` 白名单就是这条规则的实现。`three` 必须继续待在 `devDependencies`。
10. **验收断言不得为了让结果变绿而放宽或反向**（阶段 2 的教训：[§5.6.7](./PROJECT_TECHNICAL_PLAN.md#567-桌面端外壳验收实机通过但截图暴露了遮罩缺陷)）。断言要针对**用户能看到的结果**，并且每加一条都追问"它失败时画面是什么样的"。
11. **不删 `dist/` 之后再打包**：`electron-builder` 的 `files` 依赖它，`desktop:build` 会自己先 `npm run build`。
12. **文档与代码必须一致**：README 里的命令、资产路径、音频来源、数值真源，四处都不能与仓库实际状态不符。
13. **测试文件用 `#/...` 导入源码，且只写 ASCII**（`×` / `°` / `§` 写成 `*` / `deg` / `section`）；**编辑文件一律用编辑工具**，不要用 `Get-Content` / `Set-Content` 往返（阶段 4 实测会写坏多字节字符）。
