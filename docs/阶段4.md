## 1. Brief 浓缩（只保留与阶段 4 相关的部分）

### 1.1 本阶段要达成的体验落差

阶段 3 结束时，这一局是**成立**的：开局缓冲 → 8 波 → 双判据放 Boss → 打死它 → 胜负 → 重开。但它是**哑的、平的**：

| 维度 | 阶段 3 结束时的状态 | 阶段 4 要到达的状态 |
|---|---|---|
| 听觉 | **完全没有声音**。命中反馈链路只满足五路（火光 → 曳光 → 火花 → 贴花 → 伤害数字），**没有音效这一路** | 枪声、命中、换弹、敌人预警、爆炸、道具、波次、胜负全部有声；**三种关键状态能闭眼区分** |
| 视觉层次 | 白模关卡 + 单平行光 + 指数雾。结构成立，但**没有氛围**，远近没有层次 | 材质与照明成形；雾真的参与构图；投放预警 / 轰炸落点 / 爆炸溅射**同屏不混淆** |
| 性能 | 18 实体上限，**没有任何一次真机帧率读数**；"120 实体 60 FPS"是纸面目标 | **有读数**。达标就记录基线；不达标就**先优化再记录**，并把目标值按实测修正 |
| 数值 | 全部是"未经试玩的起始基线"（阶段 1 的债一直挂到现在） | 手感与节奏经过真人试玩定标；**一局 10–15 分钟从推算变成读数** |

> **核心体验关键词不变：清晰、紧凑、有节奏。** 阶段 4 的风险恰恰是**把"清晰"打磨掉**——音效堆太多会盖住预警，雾调太浓会看不见落点，Bloom 加太强会让自发光弱点糊成一片。**每一次"更好看"的改动都要回头确认"还看得清吗"。**

### 1.2 打击感的三根轴（本阶段终于要把第三根填上）

主文档 §3.4 把"手感"拆成三个**有单位、可验收**的量。阶段 1–3 只填了两根：

| 轴 | 单位 | 本项目的取值 | 阶段 4 的状态 |
|---|---|---|---|
| **打击停顿**（hitstop） | 帧 | 轻 1–2 · 中 3–5 · 重 6–12 · 暴击 +2 | ✅ 已实现（`HITSTOP`，用**模拟时间缩放**，不是跳 tick） |
| **输入响应** | ms | 轻攻击 60–120 · 重攻击 200–400 | ✅ 已实现（小敌人抬手 0.42s、大敌人 1.35s） |
| **特效同步容差** | 帧 | VFX ±0 · SFX ±1 · 镜头抖动 ±1 · 伤害数字 ±2 | ⬜ **SFX 这一路本阶段才存在**——所以这条容差表第一次真的有用 |

**这意味着阶段 4 的音效不是"加点氛围"，而是要满足一个硬性容差**：枪声必须落在与枪口火光**同一帧或下一帧**（`sfx_fire Δ ≤ +1f`）。`[HITLOG]` 已经把 VFX 那几路的实测帧差打出来了，**加音效时要给它也留一路**，否则"听起来有点延迟"会变成永远调不准的主观题。

> **从事件到发声的延迟是可以结构性消除的**：订阅 `events` 的回调发生在**产生该事件的同一个 tick**里，而 `AudioContext.currentTime` 是音频时钟。所以正确写法是"收到事件立刻 `start(ctx.currentTime)`"，**不是**"攒到下一个渲染帧再播"。后者会引入最多一帧（16.7ms）的抖动，**正好吃掉 SFX 的整个容差预算**。

| 备选 | 结果 | 代价 |
|---|---|---|
| **(a) 全部程序化合成（推荐）** | Web Audio 的 `OscillatorNode` + `AudioBufferSourceNode`（噪声）+ `GainNode` 包络，**零音频文件** | 音质上限低于预录；需要自己写十来个"合成配方"。**换来的是：零资产、零加载、双端一致、离线可跑、不需要动白名单** |
| (b) 预录文件放 `public/assets/audio/` | 音质上限更高 | 需要真人交付资产（**和人物模型一样，交付是外部依赖**）；要进 D12 白名单；**`file://` 目标上的加载路径必须单独验证**；缺文件时要有降级/静音路径 |
| (c) 混合：关键几声用文件，其余合成 | 折中 | **只在确实拿到资产时才选**。否则它等于 (a) 加一份"以后要换"的清单债务 |

> **建议 (a)，理由不是音质而是耦合**：这个项目已经因为"把可选资产当必选"绕过一次验收（阶段 2 的 `player.glb`）。音频一次有十来声，**每一只文件都是一个可能缺失的可选资产**。程序化合成把这条路整块消掉，而且它天然满足"无 CDN 依赖、可离线运行"这条阶段 5 的验收。
>
> **定了就同时写三处**：主文档 §6.3 的 D14、`config.ts` 的 `AUDIO` 分组注释、本文件 §3.1。

### 2.2 音频模块落在哪里（**不是**主文档计划期的 `core/audio.ts`）

主文档阶段 0 写的产出路径是 `core/audio.ts`。**按真实代码校正后应该是 `src/platform/audio/`**，理由三条：

1. **`src/render/**` 的模块都 `import three`**，而音频不该依赖 three——它是宿主能力，不是渲染。把音频放进 `render/` 会让一个不需要 GPU 的子系统被拖进渲染分包。
2. **`src/platform/` 已经是"宿主能力"的落点**：`Platform.ts` 在管 `localStorage` 与触屏探测，并把平台差异**探测成能力而非分支**（主文档 §2.5）。Web Audio 是同一类东西，它同样会"存在但不可用"（自动播放策略、`muted`、`file://` 限制）。
3. **它天然满足"音频不碰游戏规则"**：`platform/` 不是模拟层也不是渲染层，它只接收事件描述符。

建议的落点：

| 文件 | 职责 |
|---|---|
| `src/platform/audio/synth.ts` | **纯函数**：一个"音效描述符" → 一段可播放的音频图参数（频率、包络、噪声量、时长）。**不碰 `AudioContext`**，因此可在 Node 里单测 |
| `src/platform/audio/mixer.ts` | 声源池、总线增益、并发上限、节流、静音。**唯一接触 `AudioContext` 的地方** |
| `src/platform/audio/triggers.ts` | **纯函数**：`GameEvent` → 一个或多个"该发声"描述符（含分层增益与优先级）。**这是可测的那一半规则** |
| `src/main.ts` | 订阅 `events` → 调 `triggers` → 喂给 `mixer`；解锁手势；音量 UI |

### 2.3 D2 / D3 / D5（原计划就留给阶段 4 的三项）

| 编号 | 议题 | 建议与判据 |
|---|---|---|
| **D2** | 是否为敌人也提供美术模型 | **建议不做**。当前两种敌人的剪影是**刻意按四条轴拉开距离**的（尺寸 / 比例 / 配色 / 动作节奏，`enemyView.ts` 顶部注释写了理由），而且**共享几何与材质**。换成外部模型会：① 引入两条新的可选资产加载路径（人物模型那条至今**从未被真正的 `.glb` 加载过**）；② 让"一眼可辨"这条验收从"已用几何保证"退化成"取决于拿到的模型"。**要把美术预算花在关卡与光照上，那里单位收益高得多。** |
| **D3** | 是否引入后处理 Bloom | **先测再定**，判据是**实测帧率**：在性能场景下开/关各测一次，如果代价 ≤ 1ms 且自发光元素（敌人弱点 / 投掷物 / 预警环）的可读性有可感提升，就开；否则不开，**并把"不开"的理由写进 §6.3**。注意一个反向影响：**Bloom 会让自发光糊开，而投放预警环与轰炸落点的可读性正依赖"边缘清晰"**——如果开了 Bloom 之后两种地面圈开始互相混淆，那就是不值的信号。 |
| **D5** | 关卡是否从程序化升级为手工建模 | **建议不做**。理由是几何真源的约束（§3.3）：`game/level.ts` 的 `props` 同时派生**视觉 / 移动碰撞 / 子弹遮挡**，换成 Blender 导出的 glTF 就必须再建一套碰撞描述，**"能看见的墙"与"能挡住子弹的墙"会立刻开始漂移**。要做的话得先解决"从 glTF 生成 `collisionBoxes` / `blockers`"，那已经超出 1 周。**改成"把 `props` 调得更好看 + 加强 `decor` 通道"** |

### 2.4 D15（本阶段新增）

| 议题 | 建议 | 判据 |
|---|---|---|
| 是否引入 `three-mesh-bvh` | **倾向不引入** | 权威命中判定是**解析式**（`core/math/intersect.ts` 对 AABB / 球），**BVH 只可能加速表现层拾取**。判据：先测 `stepMs` 里射线查询占多少——**占不到 1ms 就不引入**（引入依赖 + 构建体积换不到东西）。如果确实引入了，要注意它**不能**变成命中判定的一条新路径，否则"5m 的墙永远赢过 9m 的敌人"这条规则就有了第二份实现 |

### 3.2 建议实施顺序（每一步都能独立验收）

1. **先接通性能场景**（半天）。**在美化任何东西之前**拿到第一份读数。顺序反了的话，你会在改动一堆之后不知道哪个改动贵。
2. **定 D14，然后写纯函数触发器**（半天）。`triggers.ts` 与 `synth.ts` 是纯函数，先把"什么事件该发什么声、多大声、要不要被节流"变成可断言的数据，再接 `AudioContext`。
3. **接混音器 + 解锁手势**（半天）。第一次有声音。**此时不要调音色**，只确认"每次该响的都响了、不该响的没响、并发不炸"。
4. **音量 / 静音 + 持久化**（半天）。这是阶段 5 也依赖的产出，别拖到最后。
5. **处理雾的死字段，再调氛围**（半天）。**先修字段再调值**——否则你会花时间拧一个没接线的旋钮。
6. **关卡美化**（1 天）。只动 `props` / `decor`。改完立刻跑一次 §3.3 的碰撞断言。
7. **对象池审计 + 阴影优化**（1 天）。**每一项都用性能场景前后对比**，不要凭感觉说"应该更快了"。
8. **性能场景复测 + 定 D3（Bloom）**（半天）。这是唯一能回答"值不值"的时刻。
9. **数值终调 + 真人试玩**（1–2 天）。**这是本阶段真正的产出**，不是收尾杂事。
10. **回归 + 纪要**（半天）。`typecheck` / `test` / 两次性能读数 / 实施纪要进主文档 §5.11 + 同步 skill。

> **顺序纪律**：**#0 不做完不要开始美化。** 美化与音效都会让帧率下降；没有基线，你就没有"掉了多少"这个数字，于是"要不要保留这个效果"变成一个无法回答的问题。

### 3.3 关卡美化的硬约束（**本阶段最容易造成玩法回归的一处**）

`game/level.ts` 的 `props` 是**唯一真源**，它同时派生三样东西：

```
props ──┬──► levelView.ts 的 InstancedMesh        （看得见的）
        ├──► LevelData.collisionBoxes             （走得动的边界）
        └──► LevelData.blockers                   （打得穿的边界）
```

所以：

- **加"纯装饰、不参与任何判定"的东西** → 走 `Decor` / `level.decor`（它从不进碰撞世界，也从不被射线命中）。
- **改 `props` 的尺寸/位置** → 会**同时**改视觉、移动碰撞与子弹遮挡。这是设计意图（"能看见的墙"与"能挡住子弹的墙"只能是同一堵墙），**但你必须知道自己在改三件事**。
- **不要"顺手"把围栏的 `blocksShots: false` 改成 `true`**。围栏**挡人不挡子弹是刻意的**——一堵看得见却能吃子弹的边界会读成"隐形墙"（`game/level.ts` 顶部注释写着这条）。
- **改完必须有一条断言**："美化前后 `collisionBoxes.length`、`blockers.length` 与 `ARENA_HALF_SIZE` 不变"，或者更精确地断言"出生点周围 N 米内没有新增碰撞盒"（阶段 1 踩过这个坑：掩体挡住出生点，第一步就撞箱子）。

### 3.4 性能场景怎么接（#0 的展开）

**目标**：一条命令能制造 120 个实体、跑一段固定时长、并把 `fps` / `stepMs` / `renderMs` / 最长帧间隔写进 `report-*.json`，同时留一张截图。

三条路，按推荐顺序：

| 方案 | 做法 | 代价 |
|---|---|---|
| **(a) 扩展验收工具（推荐）** | 给 `tools/desktop-acceptance.mjs` 加 `--scene perf`：连上 CDP 后注入一段"按配置数量投放敌人、并让玩家满射速"的驱动，跑固定秒数后读 `LoopMetrics` | 需要给验收工具加一个场景分支。**但它已经是唯一能启动真实外壳、读帧时钟、留 `report` + 截图的入口**，而且它跑的就是**要验的那份构建** |
| (b) 受门控的调试投放档 | 在 `World` / `Director` 加一个"性能档"：`debug:enabled` 为真时把并发上限抬到配置值、并忽略清场判据 | 要给模拟层加一条**只服务于测量**的分支。**可以接受，但必须门控在 `debug:enabled` 下**，并且**不能**成为第二条"谁负责刷怪"的真相（阶段 3 刚把这类东西整块删掉） |
| (c) 只在 Node 里测模拟层 | 整机测试里直接 `spawn` 120 个敌人，测一整 tick 的耗时 | **模拟层不依赖 WebGL**，所以这条路真的可行，而且是**唯一能在本机沙箱里跑的那条**。但**它测的是 CI 机器，且完全没有渲染**——所以它只能当"模拟 tick ≤ 2ms"的**下界证据**，**不能**当"60 FPS"的证据 |

> **建议 (a) + (c) 一起做**：(c) 给出一条能进 CI 的性能用例（`tests/perf.test.ts`），(a) 给出一条真机证据。**(b) 只有在 (a) 做不动时才考虑**——它的代价是往模拟层里塞一条只为测量存在的规则。
>
> ⚠️ **不要用 `Math.random()` 或时间随机化场景**：性能场景必须**可复现**（同一实体数、同一射速、同一时长），否则两次读数不可比。投放用固定种子。

### 3.5 音效清单（先列清楚再写合成配方）

面板要覆盖的是**玩家需要据此做决定**的声音。按优先级：

| 优先级 | 事件 | 声音要传达的信息 | 备注 |
|---|---|---|---|
| **P0** | `enemy:telegraph`（`kind: 'melee'`） | "有东西要打你了" | **这是玩家判断"该后撤了"的唯一依据**（主文档 §1.6），音效必须与躯干前倾 + 体表发光**同帧** |
| **P0** | `enemy:telegraph`（`kind: 'barrage'`，第二次发射带 `impactPoints`） | "这块地要炸了" | 与 `barrage:impact` 的爆响**必须是两个声音**，否则"预警"与"命中"听着一样 |
| **P0** | `shot:fired` | 射速反馈 | 640 RPM = 每秒 10.7 次。**必须节流/复用声源**，不能每次开新节点（§6 陷阱 3） |
| **P0** | `hit:registered`（按 `zone` 分层） | "打中了" / "打中头了" | 弱点击中要有**明确的音高上移或第二层**，否则"瞄头"的奖励只有视觉 |
| **P1** | `enemy:died` | "少了一个" | 与命中声区分；大敌人的死亡要明显更重 |
| **P1** | `spawn:pending` | "那个方向要出怪" | 与 `enemy:telegraph` **必须可区分**——一个是"通知"，一个是"反应窗口"（`config.ts` 里这两个时长是分开的字段，同一个道理） |
| **P1** | `weapon:magazineEmpty` / `reloadStarted` / `reloadFinished` | 换弹节奏 | 空仓与未空仓的换弹时长不同（1.7 vs 2.1），声音可以呼应 |
| **P1** | `item:thrown` / `item:exploded` | 投掷与爆炸 | 爆炸是全场面最大的一声，**要给它优先级与 ducking**（压低其他声部） |
| **P2** | `wave:started` / `wave:cleared` / `boss:spawned` / `boss:died` | 节奏与压力 | 与 HUD 的 `banner()` **同时**发生 |
| **P2** | `run:victory` / `run:defeat` | 结算 | 与结算 veil 同时 |
| **P2** | `player:damaged` | 受伤方向感 | 主文档提到 HUD 的暗角已经承担方向；音效可作补充（**不要**做成两个都在抢注意力） |
| **P3** | `bullet:impact`（按 `surface`） | 打在什么材质上 | 信息价值低、频次高（每秒十来次），**建议合并到 `shot:fired` 的尾音里或不单独做** |

**分层（`AUDIO` 分组建议的形状）**：`master` / `weapon` / `impact` / `enemy` / `world` / `ui` 六条总线增益 + `maxConcurrentSources` + 每类的节流窗口 + `duckingAmount` / `duckingDecay`。**全部进 `config.ts`。**

## 4. 数值基线

### 4.1 `AUDIO` 是全新的（现在一个字段都没有）

| 建议字段 | 作用 | 起点建议 |
|---|---|---|
| `masterVolume` / `muted` | 总增益与静音 | 0.7 / false（静音状态持久化到 `SETTING_KEYS`） |

### 4.3 阶段 3 留下的派生验算（调数值时用来判断"是不是调过头了"）

| 指标 | 计算 | 结果 |

### 4.4 帧时间怎么分（性能读数的诊断顺序）

拿到一次 `--scene perf` 的读数之后，按这个顺序归因：

| 症状 | 先看哪里 | 常见原因 |
|---|---|---|
| `stepMs` 偏高（> 2ms） | 敌人条数 × 每 tick 的遍历次数 | 分离力是 O(n²) 的候选；命中查询遍历全部条目（含尸体——**但回收判据已经是 `health > 0`，尸体不会留超过一 tick**）；投放点采样每次 24 个候选 |
| `renderMs` 偏高、`stepMs` 正常 | draw call 数 + 阴影 pass | **阴影是第二次遍历**：所有 `castShadow` 的物体在阴影 pass 里再画一遍。尸体仍在投影（`enemyView` 只做缩放不做 `castShadow = false`，`collapse()` 期间 1.4s 白画）；关卡的 ~120 个实例也全在投影 |
| `fps` 低但 `stepMs` + `renderMs` 都正常 | `stepsLastFrame` / `droppedStepFrames` | 说明是在追赶（`SIM.maxStepsPerFrame` 触顶）。**不要为了这个数字去调大 `maxStepsPerFrame`**——那是防死亡螺旋的保护（主文档 §4.5） |
| 帧率随时间缓慢下降 | 各池的槽位数、`enemies.targets.length` | **这是池泄漏的典型曲线**。阶段 2 / 3 各修过一个（按数组下标认领 → 按种类；`alive` vs `health > 0`）。新加的东西（音效声源）也要按这条查 |
| 偶发长帧（spike） | 首次出现某种材质/几何的时刻 | **着色器编译**。`enemyView` 是**每个身体各建一份材质**（共享几何不共享材质），所以池子的第一批身体会各触发一次编译。**预热（在加载期建好每种 kind 的 body）能消掉这个 spike** |

## 5. 硬规则（违反即驳回）

继承主文档 §2.2 / §4.1 与阶段 3 §5，阶段 4 每条都要遵守：

1. **`src/game/**` 不得 import Three.js 渲染类**（`Mesh` / `Scene` / `Material` / `WebGLRenderer`）。纯数学类型可以，但优先用项目自己的 `core/math/vec3.ts`。**本阶段不要往模拟层加任何东西——除了性能场景的门控（且必须受 `debug:enabled` 约束）**。
2. **`src/render/**` 不得包含游戏规则判断**（不出现"如果血量小于 0"）。
3. **只有 `src/main.ts` 允许接触 `document` / `window`**（`src/platform/` 接触的是宿主 API 而不是 DOM 元素，`localStorage` / `matchMedia` 已经在里面了；**音频同理：`AudioContext` 属于宿主能力，放 `platform/audio/`**）。
4. **所有数值进 `src/core/config.ts`**，任何地方不得出现魔法数字。**新增的 `AUDIO` 分组、阴影范围、雾密度、性能场景的实体数，全部要进表。**
5. **所有时间相关的量必须乘 `dt`**；冷却/射速用累加器。**音效的节流窗口归属这条规则的管辖范围**（不要用 `Date.now()` 差值做游戏逻辑判断）。
6. **hitstop 用模拟时间缩放实现，绝不"跳过 N 个 tick"。**
7. **随机一律 `core/math/rng.ts` 的可播种 `Rng`**，禁止 `Math.random()`。**合成音效的噪声缓冲也要用 `Rng` 填充**——否则"同一发枪声"每次都不同，回放/演示就不可复现（§6 陷阱 4）。
8. **短生命周期对象必须池化**。**音频的声源节点也是短生命周期对象**——它们比 Mesh 更贵（每个 `OscillatorNode` 都要挂到图上并在结束后摘掉）。
9. **攻击抬手时间（telegraph）永远不可压缩**——**它的音效必须与之同帧**，不能因为混音排队而迟到。
10. **命中查询保持解析式**（`core/math/intersect.ts`），**不要把权威判定换成 `Raycaster`，也不要引入第二条碰撞路径**（这是 D15 的判据）。
11. **弹道方向取自 `PlayerState` 的 yaw/pitch**，绝不取自渲染相机姿态。
12. **测试文件用 `#/...` 导入源码**，且**只写 ASCII**（`×` / `°` / `§` 改成 `*` / `deg` / `section`——早前有 12 处注释因此被编码往返损坏）。
13. **音效只订阅事件，不改模拟层**（阶段 4 新增）：音频是表现层，它**订阅 `events`**，绝不接受模拟层的直接调用。**不要为了"让音效更准"而往模拟层加回调**——那会立刻破坏"模拟层零渲染依赖"这条规则。
14. **不改阶段 1–3 已定案的约定**：单仓库（路由 A）· `health > 0` 回收判据 · 按种类认领视图 · `player:damaged` 单向事件 · 槽位按完成攻击数轮转 · 遮罩与 HUD 互为反面 · 一局 8 波 + 每 3 波喘息波 · 投放点边界第一道且永不放松 · 并发上限要算"已下达未落地"的订单 · 小敌人弱点倍率 2.8 · 大敌人 HP 2400（口径：躯干 110 发 / 爆头 69 发）。
15. **美化不得改变玩法几何**（阶段 4 新增）：改动 `game/level.ts` 的 `props` 会同时改碰撞与挡弹（§3.3）。**改完必须跑碰撞断言。**

## 6. 本阶段的已知陷阱

| 陷阱 | 症状 | 正确做法 |
|---|---|---|
| **先美化后测性能** ★ | 帧率掉了却不知道是雾、是阴影、还是音效造成的；于是无法决定砍哪个 | **性能场景是第 0 件事**（§3.4）。改动前后各测一次，**每个效果都要有"它值多少 ms"的数字** |
| **顺手用文件式音效** ★ | `new Audio('/assets/audio/x.ogg')` → 一条必然失败的加载；`desktop:accept` 报 FAIL；阶段 5 的"无 CDN"验收被污染 | 先定 [D14](#21-第-0-件事定-d14音效的来源)，**推荐全部程序化合成**。若真要文件，白名单 / `file://` 验证 / 缺文件降级**三件事一起做** |
| **每次开枪 new 一个 `OscillatorNode` 且不 disconnect** | 长时间游玩后帧率缓慢下降、内存上升；严重时音频引擎自己卡住 | 节点必须**在 `onended` 里摘除**；枪声走**声源池 + 节流**（`maxConcurrentSources` / `throttleMs`）。这是"每发子弹 new 一个 Mesh"在音频侧的同一张脸 |
| **合成噪声用 `Math.random()`** | 同一种子的两次回放听起来不同；单测无法断言波形 | 噪声缓冲用 `Rng` 填。**合成配方本身应当是纯函数**（`synth.ts`），因此"给定描述符 → 给定波形"是可测的 |
| **音量 UI 破坏了遮罩 / HUD 的可见性契约** | 暂停/结算时音量面板被 HUD 盖住，或者反过来；`tests/hud.test.ts` 变红 | 可见性契约是纯函数 `hudVisibility()`（4 例钉着方向）。**音量面板要么是 veil 的一部分，要么是完全独立的第三层**——**不要塞进 `#hud`**（它的 `pointer-events: none` 会让控件点不动） |
| **在别处新注册一个 `keydown` 监听** | 静音键在指针锁定/失焦时行为不一致；`preventDefault` 与其他绑定的处理不一致 | 按键一律进 `core/input.ts` 的 `BINDINGS`。**音量滑杆是 DOM 控件，不走键盘**（§1.4） |
| **音频上下文在用户手势之前创建** | 控制台一片 `The AudioContext was not allowed to start`；桌面端首帧报错 | 在**第一次点击**（`start()` 请求指针锁定那一下）里创建/`resume()`。**这也意味着音频模块必须容忍"上下文还不存在"**——`triggers` 先算描述符，`mixer` 直接丢弃直到解锁 |
| **音效在渲染帧才播放** | 枪声比枪口火光晚最多 16.7ms，正好吃满 SFX 的 ±1 帧容差 | 在**事件回调里立刻 `start(ctx.currentTime)`**（回调就发生在产生该 tick 的同一帧）。**不要在渲染回调里攒一帧** |
| **雾的"旋钮"没接线** | 改了 `RENDER.fogNear` 画面毫无变化，于是花时间怀疑别的 | **先修字段再调值**（§3.1 #6）。现在生效的是 `FogExp2` 的**密度**（`1.25 / arenaSpan`），近远字段是死的 |
| **美化改了 `props` 但没跑碰撞断言** | 玩家第一步撞在新增的箱子上；或者某堵墙突然能穿子弹了 | 走 `decor` 加纯装饰；改 `props` 后**必须**跑"碰撞盒数量与边界不变"的断言（§3.3） |
| **Bloom 让两种地面圈混淆** | 投放预警环与轰炸落点在 Bloom 下糊成同一片橙光，玩家分不清"要出怪"还是"要炸了" | 这两个圈本来就是**靠尺寸与颜色区分**的（1.5/3.2m，青/橙）。开 Bloom 后**必须重新目视这一条**；分不清就不开（D3 的判据） |
| **为了 `fps` 数字调大 `maxStepsPerFrame`** | 卡顿时不再追赶，但下一帧更卡，进入螺旋 | `maxStepsPerFrame` 与 `maxFrameDelta` 是**防死亡螺旋的保护**（主文档 §4.5）。**不要动它们**；性能问题要在 `stepMs` / `renderMs` 上解决 |
| **把"120 实体"写死在验收脚本里** | 文档说 120、脚本里是 200，两条真相 | 实体数进 `config.ts`，脚本读配置；**并在 §6.1 数值表留一行摘要**（§0.4 第 5 条约定） |
| **数值"调了一堆"但没有试玩读数** | 手感变化无法归因，也无法回退到"上一版更好"的那个状态 | §4.3 的读数要**记下来**（第几波吃力、Boss 战秒数、总时长）并写进主文档 §0.1。**没有读数的调参等于换个随机数** |

## 附录 A · 关键接口草案（供落笔时对齐）

```ts
// platform/audio/triggers.ts —— 纯函数：事件 -> 该不该发声、发什么
// 这一半是可测的规则；混音器只负责把描述符喂给 Web Audio。

/** 音效分层。每条总线在 AUDIO.busGain 里有一个增益。 */
export type AudioBus = 'weapon' | 'impact' | 'enemy' | 'world' | 'ui' | 'uiStinger';

/** 合成配方。纯参数，不含任何 Web Audio 对象。 */
export interface SoundSpec {
  readonly id: string;
  /** 基频，Hz。噪声类音效用 0 表示"无音高"。 */
  readonly frequency: number;
  /** 频率在时长内的滑动比例（1 = 不滑）。爆炸与下滑音用它。 */
  readonly frequencySweep: number;
  /** 包络，秒。 */
  readonly attack: number;
  readonly decay: number;
  /** 噪声与振荡的混合比，[0, 1]，1 为纯噪声。 */
  readonly noiseMix: number;
  /** 低通截止，Hz。用来把"闷响"与"脆响"分开。 */
  readonly lowpass: number;
  /** 噪声缓冲的种子。让同一发枪声每次可复现。 */
  readonly noiseSeed: number;
}

/** 一次发声请求。 */
export interface SoundRequest {
  readonly spec: SoundSpec;
  readonly bus: AudioBus;
  /** 相对该总线增益的局部增益，[0, 1]。 */
  readonly gain: number;
  /** 优先级；并发到顶时低优先级的先被丢弃。爆炸应当最高。 */
  readonly priority: number;
  /** 轻微的音高随机化，[0, 1]，让连发不机械。 */
  readonly pitchJitter: number;
}

/** 一个事件可以触发 0..n 个声音（例如弱点命中 = 命中层 + 金属层）。 */
export function soundRequestsFor<K extends GameEventName>(
  name: K,
  payload: GameEvents[K],
): readonly SoundRequest[];

// platform/audio/mixer.ts —— 唯一接触 AudioContext 的模块
export interface AudioMixer {
  /** 在第一次用户手势里调用。之前所有请求都被丢弃，不报错。 */
  unlock(): void;
  /** 收到触发器给出的请求。未解锁时是 no-op。 */
  play(request: SoundRequest): void;
  /** 推进一步：摘掉结束的节点、按 dt 恢复 ducking。 */
  update(dt: number): void;
  setMasterVolume(volume: number): void;
  setMuted(muted: boolean): void;
  /** 当前活跃声源数。调试面板与性能用例读它。 */
  activeSourceCount(): number;
  dispose(): void;
}

// core/config.ts —— 新增分组（形状建议，值由试听定）
export const AUDIO = {
  masterVolume: 0.7,
  busGain: { weapon: 0.9, impact: 0.7, enemy: 0.8, world: 0.75, ui: 0.5, uiStinger: 0.6 },
  maxConcurrentSources: 24,
  throttleMs: { shot: 45, impact: 25, enemyVoice: 120 },
  duckingAmount: 0.45,
  duckingDecayMs: 350,
  /** 同步容差预算，供 [HITLOG] 判定 sfx_* 的帧差是否合格。 */
  sfxLatencyBudgetFrames: 1,
} as const;
```
