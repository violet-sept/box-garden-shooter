## 1. Brief 浓缩（只保留与阶段 3 相关的部分）

### 1.1 一局的目标体验曲线（这是本阶段的验收标尺）

| 阶段 | 时长 | 玩家感受 | 系统在做什么 |
|---|---|---|---|
| 熟悉 | 0:00–0:30 | "这地方多大？枪手感如何？" | **空场地** + 计时器，允许无压力试枪（`DIRECTOR.openingGracePeriod = 4s` 是它的雏形，太短，见 §4.4） |
| 升温 | 0:30–3:00 | "它们在包我，得动起来" | 小敌人 3–6 只成波投放，逼玩家走位 |
| 压力 | 3:00–6:00 | "弹药有点紧，注意换弹时机" | 小敌人数量爬升（`smallCountGrowth`），投放间隔缩短 |
| 转折 | 6:00–7:30 | "大块头来了，杂兵还没清完" | 大敌人登场（**清场或超时**），两种模组同时施压 |
| 收束 | 7:30–12:00 | "先躲轰炸，再处理小兵" | 双模组优先级判断，**道具投掷成为翻盘手段** |

**核心体验关键词：清晰、紧凑、有节奏。** 不追求拟真，不追求叙事。

### 1.2 投放规则（硬性需求，本项目最核心的一条）

```
波次开始
   │
   ├─► 小敌人按 spawnInterval 逐个投放（受 maxConcurrentSmall 并发上限约束）
   │
   └─► 同时启动两条"大敌人解锁"判据，取先满足者：
         (A) 小敌人全部被消灭   ← 玩家行为驱动（熟练玩家能主动加速进 Boss 战）
         (B) 计时器到期          ← 时间兜底（Wave1: 75s，每波 ×0.97，下限 40s）
```

- **(A) 或 (B) 任一满足即解锁大敌人**，两者保证：熟练玩家有正反馈，卡关玩家不会无限拖。
- 大敌人存活期间小敌人**继续以较慢间隔补充**（`addsWhileBossAlive`），避免"打完 Boss 就没事干"的空窗。
- **投放点四项筛选**（顺序不能换，见 §3.6）：**① 在场地内** → ② 距玩家 14–40m → ③ 不在视野正前方 60° 锥内 → ④ 彼此间隔 ≥3.5m。全部被过滤时**逐条放宽**（先松 ④，再松 ③，最后才松 ②），**绝不允许"刷不出怪"，也绝不允许放宽到 ①**。

### 1.3 道具（`E`）与胜负

- `E` 键投出抛物线投掷物：`ITEMS.fuse = 1.4s` 引信，`blastRadius = 5.5m`，中心 `130` 伤害、**线性衰减到边缘为 0**，并给范围内的敌人一个击退冲量（`blastImpulse`）。
- 初始 3 个（`startingCharges`），**每清一波 +1**（`chargesPerWaveCleared`），上限 5（`maxCharges`）。计数已经在 `World.charges`（setter 已夹取）与 HUD 上就位。
- **胜负**：大敌人被打死且所有波次走完 → `VICTORY`；玩家死亡 → `DEFEAT`。两者都要**停住投放**、给出结算画面、并能**点击重开**。

### 2.3 建议实施顺序（每一步都能独立验收）

1. **先修验收门槛**（30 分钟）。不修，后面每一次跑验收都要先做一次人工归因。
2. **定 D13 并落字段**（30 分钟）。**然后**再写 `waves.ts`——`planWave` 的形状取决于"一局有几波"。
3. **`waves.ts` + `tests/waves.test.ts`。** 纯函数、零依赖，先把"难度曲线"这个唯一会被反复调的东西变成可断言的数据。
4. **`spawnPoints.ts` + 单测。** 也是纯函数：输入玩家位置 / 朝向 / 已有选中点 / `Rng`，输出一个位置。**边界过滤写第一个**（§3.6）。
5. **`Director.ts` + 单测。** 纯状态机：输入"这一 tick 的世界事实"（`smallAlive` / `bossAlive` / `playerDead` / `dt`），输出"要做什么"（投放哪个 archetype、在哪、要不要发事件）。**它不碰 `EnemyStore`**，只产出意图——这样三条解锁路径都能在没有世界的情况下测。
6. **接进 `World.tick`（第 10 步），同时删掉 `DEBUG_ENEMIES`。** 这一步做完，游戏就从"调试编队"变成"真的波次"了——**这是本阶段的第一个可玩里程碑**。
7. **投掷物 + 爆炸。** 纯模拟层，先不用管渲染：`tests/items.test.ts` 全绿之后再接表现层。
8. **胜负与重开。** `player:died` 已经有人发了；补 `run:victory` / `run:defeat`，HUD 用 `showVeil` 显示，点击重开走 `world.reset()`（它已经会把玩家、武器、敌人、charges 一起复位）。
9. **表现层**：投放预警（生成前的落点特效）、投掷物模型（`SphereGeometry` + 自发光）、爆炸（复用 `effects.ts` 的粒子与贴花）。
10. **回归**：`npm run typecheck && npm run test`、目视一局、把实施纪要写进主文档 §5.9 + 同步 skill。

> **顺序纪律**：**5 → 6 之前不要写投掷物**。先把"波次真的推起来了"跑通，再接道具；两件事同时做会让"这一波为什么没刷怪"变成一个有多种解释的问题。

## 3. 现状接线（从这里接上去）

### 3.1 `World.tick()` 的真实顺序（**注意：函数头注释的编号与函数体不一致**）

函数体（`src/game/World.ts`，这是权威）：

```
tick(dt, intent):
  1. 时间缩放（hitstop：scaledDt = dt * 0.12，预算按真实 dt 递减）
  2. 武器决策          tickWeapon(...)
  3. 玩家移动 + 无敌帧 + 回血
  4. 重解瞄准          refreshAim()
  5. 敌人 AI           enemies.tick(context)        ← 必须在 6、7 之前
  6. 命中盒重建        enemies.sync(scaledDt, time)
  7. 射击              performShot() + 后坐力
  8. 清理              for (const e of enemies.targets) if (e.health <= 0) enemies.despawn(e)
  9. 调试重生          if (options.debugEnemies) { ... }   ← 本阶段整块删除
```

⚠️ **实测事实**：函数**头注释**写的是 `8. Items: (phase 3) ...` / `9. Cleanup: ...`，而**函数体**里第 8 步是清理、第 9 步是调试重生。**注释是阶段 1 留下的，已经和代码错开了一格。** 落笔时**顺手把头注释改对**（别只改代码不改注释，那正是这份文档在纠的毛病）。

### 3.2 导演插在哪里：**放在 tick 末尾（清理之后）**

```
  ... 7. 射击
  8. 投掷物：积分 + 反弹 + 引信 + 引爆        ← 新增（取代头注释里那个从来没实现的 "8. Items"）
  9. 清理：回收死亡实体、归还槽位              ← 已有，判据是 health > 0
 10. 导演：波次状态机 + 投放 + 胜负判定        ← 新增
```

| 位置 | 放什么 | 理由 |
|---|---|---|
| 第 8 步（射击之后、清理之前） | 投掷物的弹道积分与引爆 | 爆炸要走 `EnemyStore.applyBlast`，而它读的是**这一 tick 的敌人位置**——所以必须排在 `enemies.tick` / `enemies.sync` 之后。放在清理之前，是因为被炸死的敌人要和被打死的走**同一条**回收路径 |
| 第 10 步（清理之后） | `director.tick(...)`：推进波次、决定投放、判定胜负 | **`liveCount()` 读到的必须是"清理后"的数量。** 放在清理之前，计数里会带上本 tick 即将回收的尸体，于是"清场判据"与"并发上限"都会差一 tick |

**代价与取舍**：第 10 步刷出来的敌人，这一 tick 不会被 AI 推进（它的 `fsm` 初始是 `'SPAWN'`，本来就有入场时间），因此**不可察觉**。若你选择把导演放在第 5 步之前，就必须自己承担"计数含尸体"的后果并在注释里写清楚——**两种都可以，但必须在代码里写明为什么**。

### 3.3 `EnemyStore` 的现成接口（**直接用，不要新写一个敌人仓库**）

主文档决策 **D10 / 路由 A**：敌人只有**一个**仓库，练习靶是 `kind: 'dummy'`。阶段 3 只需要调用它：

| 接口 | 签名要点 | 阶段 3 怎么用 |
|---|---|---|
| `spawn(archetype, position, options?)` | `options: { healthScale?, state? }`；`state` 默认 `'SPAWN'` | 投放点筛选之后调用，传波次血量缩放。**位置是外部注入的**——`spawn` 不会自己找地方站 |
| `despawn(enemy)` | 释放槽位 + 回收，幂等 | 清理步骤已经在用；**不要在遍历中正序调用**（§6 陷阱 2） |
| `liveCount(kind?)` | **排除 `dummy`**，只数 `alive` | 双判据的"清场"判据、`maxConcurrentSmall` 上限、`addsWhileBossAlive` 的补充判据 |
| `aliveCount()` | 不排除 `dummy` | 调试面板/统计用。**两个函数不要合并**（合并后要么波次把靶子算成敌人，要么面板看不到靶子） |
| `applyBlast({ ownerId, position, radius, damage })` | 半径**线性衰减**、边缘伤害下限 1；跳过 `id === ownerId`；**对靶子也生效** | 投掷物引爆与 Warden 轰炸共用它。玩家投掷物传 `ownerId: 0`（没有敌人的 id 是 0，因此不会误排除） |
| `attackSlots` | 并发近战槽位 | 只读；不需要阶段 3 干预 |
| `reset()` | 倒序回收所有非靶子条目并复位靶子 | 重开时**必须**调用（`World.reset()` 已经调了） |

```ts
'wave:started'   { tick; wave: number; smallCount: number; bossTimer: number }
'wave:cleared'   { tick; wave: number }
```

### 3.6 投放点：**边界过滤必须是第一道**（本阶段最容易写错的一处）

场地只有 **±24m**（`SIM.arenaHalfSize` / `ARENA_HALF_SIZE = 24`），玩家出生在 **`(0, 0, 8)`、yaw 0（面向 −Z）**。而候选环是以**玩家**为心画的：

- 以玩家为心的 **18m 环**，在 z 正方向直接到 `8 + 18 = 26 > 24` —— **已经在围栏外**。
- 若先按距离筛出"合格点"再夹取边界，夹取会把候选点挤到围栏线上（距离条件作废）；不夹取就是把敌人刷到场地外。

所以顺序是 **① 在场地内 → ② 距离 14–40m → ③ 视野锥外 → ④ 彼此散开**，兜底时**反向逐条放宽**，永远不放松 ①。这一条同时要回写到主文档 §1.6 与 §3.2.6（已写）。

### 3.7 随机源必须**独立**（否则"同种子同序列"会碎）

`World` 里已经有一个从 `seed` 派生的 `rng`，交给了射击求解（`combat`）；`createWeaponState(seed ^ 0x9e37)` 是现成的"派生一路独立流"的写法。**导演必须同样拿一路自己派生的流**（例如 `seed ^ 0x51ed`），**不能共用 `combat` 那一流**：每发子弹的扩散要消耗两次随机数，共用会让**投放点取决于玩家这一局开了多少枪**，于是同一份种子给出两份波次，可回放性直接归零。

`main.ts` 目前调 `createWorld({ events, debugEnemies: true })`，**没有传 `seed`**，所以种子恒为 `seedFromString('box-garden')`——**每一局的波次都一模一样**。阶段 3 要决定"每局换种子"：在 `main.ts` 生成一次（例如 `Date.now() >>> 0`）并传进去，同时把它显示在 `F3` 面板或结算画面上，这样报 bug 时能复现。**`Rng` 本身仍然必须是可播种的**，只是种子来源从常量变成"每局一次"。

## 5. 硬规则（违反即驳回）

继承主文档 §2.2 / §4.1，阶段 3 每条都要遵守：

1. **`src/game/**` 不得 import Three.js 渲染类**（`Mesh` / `Scene` / `Material` / `WebGLRenderer`）。纯数学类型可以，但优先用项目自己的 `core/math/vec3.ts`。**导演、投掷物、爆炸全在模拟层——它们连 `Vector3` 都不该从 three 引。**
2. **`src/render/**` 不得包含游戏规则判断**（不出现"如果波次大于 8"）。
3. **只有 `src/main.ts` 允许接触 `document` / `window`。**
4. **所有数值进 `src/core/config.ts`**，任何地方不得出现魔法数字。
5. **所有时间相关的量必须乘 `dt`**；冷却/射速用**累加器** `x += 60 / rpm`，不用赋值。**投掷物的引信、投放间隔、波次计时器都在这条规则的管辖范围内。**
6. **hitstop 用模拟时间缩放实现，绝不"跳过 N 个 tick"。**
7. **随机一律 `core/math/rng.ts` 的可播种 `Rng`**，禁止 `Math.random()`；**导演必须用独立派生的一路流**（§3.7）。
8. **短生命周期对象必须池化**（投掷物、爆炸粒子、落点圈、贴花）——"每次扔一个 `new Mesh`"是本项目点名的头号掉帧原因。
9. **攻击抬手时间（telegraph）永远不可压缩**——**投放预警时长同理**：它是玩家判断"哪里要出怪"的唯一依据。
10. **命中查询保持解析式**（`core/math/intersect.ts`），**不要把权威判定换成 `Raycaster`**。爆炸的球形判定用 `core/math/intersect.ts` 里现成的函数。
11. **弹道方向取自 `PlayerState` 的 yaw/pitch**，绝不取自渲染相机姿态——**投掷物同样如此**。
12. **测试文件用 `#/...` 导入源码**，且**只写 ASCII**（`×` / `°` / `§` 改成 `*` / `deg` / `section`——早前有 12 处注释因此被编码往返损坏）。
13. **导演只产出"意图"，不直接改世界**（阶段 3 新增）：`Director.tick()` 返回/记录"这一 tick 要投放什么"，由 `World` 执行 `enemies.spawn(...)`。这样三条解锁路径与投放节奏都能在**没有世界**的情况下单测。
14. **不改阶段 2 已定案的约定**：单仓库（路由 A）、`health > 0` 回收判据、按种类认领视图、`player:damaged` 单向事件、槽位按完成攻击数轮转、遮罩与 HUD 互为反面。

| 陷阱 | 症状 | 正确做法 |
|---|---|---|
| **投放点先过距离再夹边界** ★ | 敌人刷在围栏外，或者"合格点"被挤到围栏线上，距离条件形同虚设 | **边界过滤放第一道**（§3.6）。候选环是以玩家为心画的，`18m 环` 在 `(0,0,8)` 处直接越界（`8+18=26 > 24`） |
| **遍历 `enemies.targets` 时正序 `despawn`** | 极少情况下某个死条目这一 tick 没被回收，多留一 tick；且与 `retire()` 的注释相矛盾 | 倒序遍历（`for (let i = len-1; i>=0; i--)`）或先快照——`EnemyStore.reset()` 就是这么写的。**这不是阶段 2 那个泄漏**（被跳过的条目 `alive` 已 false，命中查询与计数都不受影响），但别让它变成两个写法 |
| **导演和射击共用一路 `Rng`** | 同一份种子的两局，波次不同——因为玩家开枪次数不同 | 导演自己派生一路（`seed ^ 0x51ed`），照 `createWeaponState(seed ^ 0x9e37)` 的写法（§3.7） |
| **`liveCount()` 与 `aliveCount()` 用混** | 波次把练习靶算成敌人（于是"清场"永远不成立，Boss 只能靠超时出场） | "清场"与并发上限用 **`liveCount()`**（排除 `dummy`）；面板用 `aliveCount()` |
| **把 `DEBUG_ENEMIES` 留着"以防万一"** | 两处同时在刷怪，波次计数被调试编队污染，且"清场"永远不成立 | **整块删掉**（§3.8），并把仍然有意义的断言移植进新测试 |
| **胜负之后 tick 还在投放** | 阵亡画面上还在刷兵、还能被追打 | `Director` 进入 `VICTORY` / `DEFEAT` 后**立刻停止投放**；用 `playerDead` 与 `phase` 双保险。玩家死亡时 AI 已经会收到 `playerAlive: false`（阶段 2 就绪），但那不等于"停止投放" |
| **改回遮罩 / HUD 的旧行为** | 画面又被遮住，或者 HUD 与遮罩同时可见/同时隐藏 | 可见性契约是纯函数 `hudVisibility()`，`tests/hud.test.ts` 有 3 例钉着。**结算是"换文案"，不是"再写一个 veil"** |
| **投掷物每帧 `new`** | 帧率随投掷次数缓慢下滑 | 池化（硬规则 8）。投掷物数量少，但它是**每帧新建而且带几何体**的那种，比粒子更贵 |
| **爆炸只伤敌人不伤靶子 / 误伤自己** | 单测里"炸了 3 个只死了 2 个" | `applyBlast` 会对 `dummy` 生效且跳过 `ownerId`——写测试时**期望值要按这个来**；玩家投掷物传 `ownerId: 0` |
| **投放预警复用大敌人的 `telegraphTime`** | 改 Boss 抬手时长会顺手改掉投放预警 | 两者语义不同（反应窗口 vs 通知），各自一个字段（§4.2） |
| **局时靠推算当验收** | "应该差不多 10 分钟" | 局时**只能**来自真人试玩（§4.5 的推算只是选 D13 的依据） |

## 附录 A · 关键接口草案（供落笔时对齐）

```ts
// game/director/waves.ts —— 纯函数，无副作用，可播种
export interface WavePlan {
  readonly wave: number;
  readonly smallCount: number;
  readonly interval: number;
  readonly bossTimer: number;
  readonly healthScale: number;
  /** 这一波是不是喘息波（更少的小敌人、更长的空档）。 */
  readonly breathing: boolean;
}
export function planWave(wave: number, rng: Rng): WavePlan;
export function isFinalWave(wave: number): boolean;

// game/director/spawnPoints.ts —— 也应当是纯函数
export interface SpawnContext {
  readonly playerPosition: Vector3;
  readonly playerYaw: number;
  readonly chosen: readonly Vector3[];   // 同批已选中的点
}
/** 返回一个合法的投放点；全部候选被否决时返回放宽后的兜底点。 */
export function pickSpawnPoint(out: Vector3, ctx: SpawnContext, rng: Rng): Vector3;
/** 供单测直接断言的判定函数（导出它们，不要只测 pickSpawnPoint）。 */
export function isInsideArena(p: Vector3, margin: number): boolean;
export function isInViewCone(p: Vector3, from: Vector3, yaw: number, halfAngleDeg: number): boolean;

// game/director/Director.ts —— 状态机，只产出意图
export type DirectorPhase =
  | { kind: 'OPENING'; timer: number }
  | { kind: 'SPAWNING_SMALL'; wave: number; spawned: number; remaining: number; timer: number }
  | { kind: 'BOSS_LOCKED'; wave: number; remaining: number; timer: number }   // 等清场或超时
  | { kind: 'BOSS_ACTIVE'; wave: number }
  | { kind: 'INTERMISSION'; wave: number; timer: number }
  | { kind: 'VICTORY' } | { kind: 'DEFEAT' };

export interface DirectorContext {
  readonly tick: number;
  readonly time: number;
  readonly dt: number;
  readonly playerPosition: Vector3;
  readonly playerYaw: number;
  readonly playerDead: boolean;
  /** 活着的战斗单位，`dummy` 已被排除（用 EnemyStore.liveCount()）。 */
  readonly smallAlive: number;
  readonly bossAlive: boolean;
}
export interface DirectorSpawnOrder { readonly archetype: EnemyArchetypeId; readonly position: Vector3; readonly healthScale: number; }

export interface Director {
  readonly phase: DirectorPhase;
  readonly wave: number;
  /** 推进一个 tick；返回这一 tick 要执行的投放（通常 0 或 1 个）。 */
  tick(ctx: DirectorContext): readonly DirectorSpawnOrder[];
  reset(): void;
}

// game/items/throwable.ts —— 池化，与 dt 无关的弹道
export interface Throwable {
  active: boolean;
  readonly position: Vector3;
  readonly velocity: Vector3;
  fuseRemaining: number;
  lifeRemaining: number;
}
export interface ItemSystem {
  /** 扔一个（从玩家枪口/手上位置，方向取 PlayerState 的 yaw/pitch）。 */
  throwFrom(position: Vector3, yaw: number, pitch: number): boolean;
  /** 推进所有在飞的投掷物，返回这一 tick 引爆的那些的位置与半径。 */
  tick(dt: number, out: ExplosionEvent[]): void;
  clear(): void;
}
```
